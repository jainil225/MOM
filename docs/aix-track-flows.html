2. Step-by-step for a customer

  1. Sign in. Use Google sign-in, or enter an email to receive a 6-digit code. A new account gets 60 free minutes. Sessions last 30 days. A referral link (/r/<code>) records who invited the user.
  2. Capture the meeting. Upload an audio or video file (large files go up in parts, so long meetings work), or record live in the browser. A live recording is saved in pieces, so a dropped connection does not lose the whole meeting.
  3. Set options. Language (or auto-detect), speaker labels (who said what), project, category, tags, and optional instructions for this meeting only.
  4. Give consent. The user confirms they may process the recording. Nothing is processed without it.
  5. Check balance. The screen shows the minutes available. Free minutes are used first, then credits. Speaker labels use credits at twice the standard rate. If the balance is short, the user is sent to buy credits before anything is charged.
  6. Wait for processing. The progress screen moves through upload, audio preparation, transcription and MOC writing.
  7. Review the MOC. The MOC shows the summary, discussion points, decisions, action items with owners and due dates, and the next meeting. It is a draft. The user checks and edits it before sharing.
  8. Act on it. Share a read-only link, email the MOC, export to Word, email each action item to its owner, mark actions done, or regenerate the MOC.
  9. Come back later. History lists every MOC with search and tags. Actions lists open action items across all meetings. Projects groups meetings by client or engagement.

2. Upload to MOC: request sequence

sequenceDiagram
  autonumber
  participant B as Browser
  participant S as server.js
  participant DB as PostgreSQL
  participant F as FFmpeg
  participant ST as Speech-to-text
  participant AI as MOC AI
  B->>S: POST /api/upload/chunk (10 MB parts, .owner file per upload)
  B->>S: POST /api/upload/complete
  S->>S: Check owner matches session, record consent
  S->>S: Join parts into one file, save copy in uploads/media
  S->>F: Extract audio, 16 kHz mono WAV, trim silence
  F-->>S: WAV + duration (refuse above MAX_AUDIO_HOURS)
  S->>DB: Credit preflight (free minutes, then credits)
  alt Not enough
    S-->>B: 402-style error, ask to buy credits
  else OK
    S->>ST: Transcribe (diarized job, batch job, or 29 s chunks x3)
    ST-->>S: Transcript + language (+ speaker segments)
    S->>DB: Read recent meetings and open actions for context
    S->>AI: Master prompt + user instructions + transcript
    AI-->>S: MOC as JSON
    S->>DB: INSERT mom_sessions, moc_prompt_log
    S->>DB: Deduct credits, write credits_log, api_usage_log
    S-->>B: MOC JSON
    S-)S: Offload file to Google Drive if connected
  end

Live recordings follow the same pipeline after /api/recordings/start, ordered /api/recordings/:id/chunk calls and /api/recordings/:id/status. The single-request route /api/transcribe does the same work for small files and also accepts an optional context image.

4. MOC writing (AI step)

flowchart LR
  T[Transcript
+ language hint

+ user and session instructions] --> Q{Keys configured}
  Q -- Claude + OpenAI --> A1[GPT-4o writes a
short meeting brief] --> A2[Claude writes MOC
master prompt + brief]
  Q -- Claude only, or brief failed --> A3[Claude writes MOC]
  Q -- OpenAI only --> A4[GPT-4o writes MOC]
  A2 --> O[Parse JSON
save mom_sessions
log full prompt to moc_prompt_log]
  A3 --> O
  A4 --> O
  • Master prompt versions live in master_prompts; one is active. Default text is prompts/master-moc-prompt.md.
  • User and session instructions are added to the master prompt. They do not replace it.
  • The prompt tells the model to treat meeting content as data, not to invent owners, dates or decisions, and to mask secrets.
  • If the AI step fails after transcription, the transcript is saved as a draft so the paid transcription is not lost.

6. Recording file lifecycle

stateDiagram-v2
  [*] --> Chunks: upload parts in uploads/chunks/id
  Chunks --> Assembled: /api/upload/complete
  Assembled --> LocalMedia: copy kept in uploads/media
  Assembled --> WAV: FFmpeg working files
  WAV --> [*]: deleted in finally block
  LocalMedia --> Drive: offloadToDrive() if user connected
  Drive --> Drive: playback and re-diarize stream from Drive
  LocalMedia --> Deleted: user deletes MOC
  Drive --> Deleted: drive.deleteFile()
  Deleted --> [*]

After a successful Drive upload, mom_sessions stores drive_file_id, sets storage_provider = 'drive', clears file_path, and only then deletes the local copy. A sweep retries pending uploads when a user connects Drive.
